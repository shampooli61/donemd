# #113 从文件 App 打开 Markdown

远端：https://github.com/shampooli61/donemd/issues/113 。关联 #105、#109、#111。

## 行为
- Files 传入 `.md` / `.markdown` 本地 URL 后交给唯一文档会话，读取并保存原文件。
- 已授权目录内直接打开；未知目录显示文件名并要求选择文件所在目录，以便访问相邻附件。错误目录可重新选择；取消不会写入文档。
- 当前文档正在编辑时保留当前内容，显示待打开文件；保存返回后继续处理。重复打开当前文件不创建第二个会话；已有待处理请求时其他不同请求有明确提示。
- 下载/权限/文件缺失导致打开失败时保留重试与取消入口。拒绝远程 URL、非 Markdown 和目录。
- 不再声明系统文档浏览器 UI；保留原位打开及文件共享。

## 验证
回归先失败后通过：原位保存、目录权限前置和当前文档保护。17 项文档/文件及 3 项模拟器 UI 回归通过；真机独立冷启动用例重试后通过。热启动系统分发用例在真机受测试运行器私有目录限制，仅在模拟器执行；真实 Files 手动复验待反馈。完整结果见远端评论与 ios-device-validation.md。模拟器 URL 分发和文件系统测试不能替代真机 Files 与 iCloud 安全作用域授权。

## 真机步骤
1. 在 Files 中打开已经授权测试目录的 Markdown，确认直接进入编辑器；修改、保存、返回后到 Mac 核对原文件。
2. 从其他目录打开文档，按提示选择该文档所在文件夹，确认正文及相邻附件可访问；选错目录时保留重选入口。
3. 正在编辑第一份文档时从 Files 打开第二份：第一份内容不变，保存返回后打开第二份；取消待打开只取消新请求。
4. 文件未下载/已删除/权限失效时显示可重试错误，不修改原文件。

## 2026-10-21 授权衔接复验

用户确认已进入应用，但进入测试文件夹并点系统“打开”后仅返回目录。代码核对发现普通目录选择只更新 FolderStore，没有继续待处理外部文档；独立授权入口才会继续。合并为单一文件夹选择器，所有入口统一处理待打开请求，保留选错目录校验与重试。界面明确说明选择文件夹授权后将自动打开原文档。

新增回归用例先在仅更新目录的路径失败（未创建文档会话），用于验证选择目录后继续原文档；真实 iCloud URL / 文件提供器权限与系统选择器仍需真机复验，不能仅凭此测试认定用户的全部故障已解决。

验证结果：18 项文档/文件 + 4 项模拟器 UI 全部通过；真机签名构建通过。手机当前未连接，尚未安装此修订与真机复验。
