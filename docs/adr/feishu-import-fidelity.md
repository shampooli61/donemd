# 飞书拉取内容保留与格式版本

状态：采用。此记录补充已有的 Markdown 稳定规范化与飞书占位块约定。

## 问题

旧转换器只读取表格单元格的首个普通段落，导致标题、多段文字、图片和视频引用丢失；未识别的分栏块被转换成分割线；逐段输出行内格式会产生无效的加粗和删除线标记。

## 决定

- 表格继续使用 GFM 管道语法，保留全部单元格文字、图片及飞书占位块。标题、引用、列表等块级样式压平，内容按原顺序排列。段落以 `<br>` 分隔，管道字符转义。解析时将图片和占位块恢复为合法的 Tiptap 块节点，不能把块图片放进段落。
- 普通占位块的多行 magic comment 格式保持原约定。仅在表格单元格内，将同一注释中的换行编码为 `&#10;`、管道编码为 `&#124;`，原有 `&` 先编码为 `&amp;`。表格解析器按相反顺序恢复字段，复用原解析器；ID、token、未知字段和资源引用保持不变。旧版应用不支持这一表格内编码，应使用新版打开。
- 飞书分栏（24）与栏（25）按子块顺序展开，保留内容；未知类型保留为带原 block ID 的占位块，不生成虚假分割线。
- 相邻且格式相同的文字先合并；加粗、斜体、删除线的首尾空格移到标记外。遇到中文标点紧邻正文的 CommonMark 边界，仅将相邻正文字符写成字符实体，重新解析后恢复原字符，不插入空格或零宽字符。
- `feishu.pull_format_version` 记录最近拉取的转换格式版本。旧版本文件即便远端 revision 未变，手动拉取仍重新应用新转换结果，走已有的覆盖前快照与未保存修改检查；格式版本和远端 revision 都一致时保持原有的 no-op 行为。
- 推送仍只有顶层占位块的分段保留能力。表格、分栏或列表中的原生资源不能被误判为远端已删除；在写入前明确阻止此类推送，不提供「跳过已删除引用」操作。

## 边界

合并单元格、列宽、分栏布局、表格内标题层级/列表缩进/高亮背景，以及飞书字色仍不完整保留。视频和画板作为原生引用卡片显示，视频不下载成本地播放器。包含嵌套原生块的文档可拉取和本地阅读，编辑远端内容仍需使用飞书。

回归使用虚构内容，真实用户文档仅用于本地只读验证，不作为公开测试夹具。
