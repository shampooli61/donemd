# iOS 完整文档阅读与写作 PRD

状态：产品方案已由用户确认，实施中。日期：2026-10-19。

## Problem Statement
Done.md 用户需要在 iPhone/iPad 接着编辑 Mac 上的同一份文档，保留完整内容能力与开放的 Markdown 文件，不能因移动端保存而丢失复杂块或附件。

## Solution
提供原生 iOS 外壳与移动编辑交互，复用现有 Visual 编辑器及 Markdown 引擎。首次选择 iCloud Drive 文件夹，直接读写其中的 `.md` 与相邻 `assets/`。iCloud 负责文件传输，应用负责保存、协调读取、外部更新和冲突保护。免费 iCloud 账户可用，受账户剩余空间和网络条件影响。

## User Stories
1. 作为作者，我要选择并恢复对文档文件夹的访问、浏览子目录和按名称查找，以便打开同一份文件。
2. 作为作者，我要新建、重命名、复制和分享文档，以便管理写作；移动和删除使用系统文件 App。
3. 作为作者，我要编辑正文、标题、加粗/斜体/删除线/行内代码、链接、引用、分隔线、列表、任务和提示块，以便完整写作。
4. 作为作者，我要撤销重做、移动/复制/删除段落、查找替换，以便高效修改。
5. 作为作者，我要插入并编辑表格、代码、公式、Mermaid，以便表达复杂内容。
6. 作为作者，我要从照片或文件插入图片、视频并预览播放，以便图文写作。
7. 作为读者，我要切换阅读/编辑与只读源码、使用大纲和折叠、调整主题字号、查看统计并恢复阅读位置。
8. 作为作者，我要自动保存、在离线时编辑已下载内容，并在失败时重试或恢复，以免丢稿。
9. 作为跨设备作者，我要收到外部更新，遇到并发修改时保留版本并选择，以免静默覆盖。
10. 作为已有文档用户，我要保留原文块、frontmatter 与飞书占位身份，以免普通本地编辑损坏内容。
11. 作为键盘或辅助技术用户，我要可访问的操作入口、快捷键与可靠中文输入。

## Implementation Decisions
- SwiftUI 原生外壳 + WKWebView/Tiptap；复用现有 Markdown 引擎、附件规则与 Web 内容节点。最低 iOS/iPadOS 17，使用当前 SDK 构建。
- 手机单栏；顶部文件/标题/状态/大纲/菜单，键盘上方格式与插入操作。复杂内容使用面板或全屏编辑。iPad 同等内容能力，双栏增强后续。
- 源码只读且可复制。Visual 是正文编辑入口，原文块有独立编辑入口。规范化有实际变化时，首次写入前说明并征得用户操作确认。
- 目录通过系统选择器授权并保存访问书签。目录浏览基于真实文件，不建立笔记库、全文索引或专有格式。
- iOS 文档通过 UIDocument 协调；Mac 保留 NSDocument，核查外部更新。正文保存成功不表示远端已收到；无可靠同步证据时仅显示本地保存状态。
- 文件夹目录不等同于飞书同步根目录。保留 `.md + assets/`；多个附件不是跨文件原子事务。下载中的附件提供提示与重试。
- 离线仅保证已下载文件；恢复副本存应用支持目录。冲突不自动合并，先保留当前内容再解决系统冲突。
- 表格以 GFM 能力为限；公式 LaTeX、图表 Mermaid 源码编辑+预览。媒体无美化/剪辑/转码。首版不清理未引用附件。
- 分享纯 Markdown 或包含引用附件的打包副本，缺附件不能静默生成“完整包”。重命名/复制不覆盖同名文件。
- 原有桌面功能继续工作，iOS 无 AI/飞书操作入口，但保留已有内容。

## Testing Decisions
- 通过公开文档接口验证真实保存、重开、原文保留、外部更新与冲突保护，不仅测试状态字段。
- 沿用现有 Markdown/Assets/Web 测试；移动端添加 UIDocument 生命周期、文件操作、恢复与附件集成测试。
- Web 测试验证格式命令、替换、段落操作的实际内容及撤销；检查 TypeScript 与生产构建。
- iOS 模拟器执行应用构建、文档测试与 UI 冒烟；Mac 执行相关回归。
- 真机最终验收：中文输入/选区/键盘、VoiceOver、照片/视频、离线恢复、真实同账号 Mac+iPhone iCloud 往返与并发冲突。模拟器通过不能替代这项验收。

## Out of Scope
AI、飞书操作、多人实时协作、自建同步后端、源码编辑、全文检索/RAG、笔记库、跨目录移动/删除、表格合并单元格/计算、媒体处理、自动合并冲突、发布到 App Store。
